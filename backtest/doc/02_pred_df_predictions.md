## 一、数据结构背景与核心设计哲学

`pred_df` 是 Kronos 回测内核中的最前置 AI 预测数据载体。它是由深度时间序列大模型在严格防止未来函数泄漏的前提下，通过 **滚动前瞻（Walk-Forward）** 机制逐步推演生成的。

在每次推演中，系统采用 **蒙特卡洛多路径采样（Monte Carlo Multi-path Sampling）** 并融合 **粒子滤波（Particle Filtering, PF）** 动态分配路径权重。其底层设计贯穿了三条至关重要的量化风控原则：

1. **解耦入场期望与止盈目标（消除选择性偏置 Selection Bias）**：
   - 严禁将单路径上的最高冲高价直接当作开仓预期，否则会虚构胜率与赔率幻觉；
   - **入场判断** 严格绑定跨路径的 **无偏加权期望值**；
   - **止盈目标** 绑定逐路径极值的 **加权中位数**，完整保留错峰爆发的冲高弹性。
2. **状态感知与动态置信度（Metacognition）**：
   - 模型通过回溯比对已知验证窗口行情的拟合误差，自适应输出粒子滤波置信度 `pf_confidence`，动态约束下游入场门槛与仓位；
   - 动态识别路径到达波峰的最优时间跨度，输出自适应时界 `optimal_horizon`。
3. **严禁插值污染评估**：
   - 真实大模型前向推理的日期标记为锚点，步长填充的线性插值标记为 `is_interpolated=1`，评估与策略端严格剔除插值数据，杜绝虚高 IC 与虚假平滑。

   #### 💡 原理深度拆解：粒子滤波打分机制与权重生成全流程

   ##### (1) 机制大图景：这整套机制到底在干嘛？
   - **一句话总结**：先用“已经发生的真实历史价格”作为考卷，测试模型蒙特卡洛抽样出的每条路径；谁考得好（模拟得贴合真实走势），就给谁更高的投票权；最后依据投票权对未来多条路径加权平均，产出综合预测。
   - **粒子滤波（Particle Filter）核心思想**：系统不是孤立地赌单条预测线，而是撒出多条“粒子路径”（样本），利用近邻历史已知走势进行即时回测打分，自适应动态分配权重。

   ##### (2) 时间线梳理与回退条件（Back-in-Time Conditioning）
   以基准决策日 `2026-04-24` 为例，推演整体分为“历史考卷”与“未来前瞻”两个阶段：

   | 时间标记 | 阶段属性与含义 | 真实价格与状态 |
   | :--- | :--- | :--- |
   | **Day -2** | 决策日前第 2 天（验证窗口） | 真实价格 `99.00`（系统已知） |
   | **Day -1** | 决策日前第 1 天（验证窗口） | 真实价格 `100.00`（系统已知，即 `prev_real_close`） |
   | **Day 0 ~ Day +4** | 未来 5 天前瞻期（预测窗口） | 未知，待模型推理预测（Day 1 到 Day 5） |

   - **回退条件技巧（Back-in-Time Conditioning）**：  
     大模型在推理时一口气推演 7 天 = 前 2 天（历史考卷 `pf_val_window = 2`）+ 后 5 天（真正要输出的前瞻预测 `pred_len = 5`）。  
     系统利用已知的 `[99.00, 100.00]` 当作考卷标准答案，专门用来给这 7 天预测中的“前 2 天”打分，打完分后截断扔掉前 2 天，仅保留后 5 天（即 `close_arr` 与 `low_arr`）进入后续策略决策。

   ##### (3) 验证矩阵 `val_pred_arr`：5 条粒子对已知两天的模拟走势
   模型采样出的 5 条粒子在历史 2 天验证窗口上的模拟收盘价与真实行情对比如下：

   | 粒子路径 | Day -2 模拟价 | Day -1 模拟价 | 真实标准答案 (Day -2: 99.00 / Day -1: 100.00) | 走势贴合度直观评价 |
   | :--- | :--- | :--- | :--- | :--- |
   | **Path 0** | 100.98 | 102.00 | 99.00 / 100.00 | 紧密贴合真实价格曲线，形态逼近 |
   | **Path 1** | 101.97 | 97.00 | 99.00 / 100.00 | Day -2 偏高、Day -1 偏低，走势出现拧巴 |
   | **Path 2** | 97.02 | 102.00 | 99.00 / 100.00 | 围绕真实价轻微波动，整体贴合度高 |
   | **Path 3** | 93.06 | 94.00 | 99.00 / 100.00 | 93.06 -> 94.00 显著偏离真实（99 -> 100），明显严重画歪 |
   | **Path 4** | 100.98 | 98.00 | 99.00 / 100.00 | 整体贴近真实价格，偏差较小 |

   ##### (4) `path_nrmse`：每条路径相对跟踪误差的计算与手算拆解
   1. **为什么必须使用相对误差（Normalized RMSE），而不是绝对差价？**  
      100 元股票差 2 元（误差 2%）与 10 元股票差 2 元（误差 20%），其严重程度截然不同。除以真实价格可以彻底消除标的股价高低的量纲影响。
   2. **数学计算公式**（详见 [kronos_predictor.py: L837-L838](file:///Users/jyy/Documents/github_projects/Kronos/backtest/data/kronos_predictor.py#L837-L838)）：
      ```text
      相对误差矩阵: rel_err[i, t] = (val_pred_arr[i, t] - real_val_closes[t]) / real_val_closes[t]
      均方根相对误差: path_nrmse[i] = sqrt( mean( rel_err[i, :] ** 2 ) )
      ```
   3. **以 Path 0 为例的手算演练**：
      ```text
      Day -2 相对误差 = (100.98 - 99.00) / 99.00 = +1.98 / 99.00 = +0.0200
      Day -1 相对误差 = (102.00 - 100.00) / 100.00 = +2.00 / 100.00 = +0.0200

      均方根误差 RMS = sqrt( (0.0200^2 + 0.0200^2) / 2 )
                     = sqrt( 0.0004 ) = 0.0200 (即 2%)
      ```
   4. **5 条路径的打分输出**：
      ```text
      path_nrmse = [0.02, 0.03, 0.02, 0.06, 0.02]
      ```
      - 数值越小代表粒子模拟越贴近真实，该路径预测越靠谱；
      - Path 3 的 NRMSE 高达 0.06（6%），走形最为严重，一目了然。

   ##### (5) `w_arr`：从“误差”到“投票权重”的 Softmax 映射与数值技巧
   1. **核心直觉**：误差越小，赋予的投票权重越高。但不是简单的线性取倒数，而是采用带温度调节的**负指数 Softmax 映射**（详见 [kronos_predictor.py: L844-L845](file:///Users/jyy/Documents/github_projects/Kronos/backtest/data/kronos_predictor.py#L844-L845)）：
      ```text
      score[i] = exp( - (path_nrmse[i] - min(path_nrmse)) / temp )
      w_arr[i] = score[i] / sum(score)
      ```
   2. **为什么公式中要减去 `min(path_nrmse)`？**  
      这是量化与机器学习中极其标准的**数值稳定性技巧（Numerical Stability Trick）**。如果不减去最小值，当误差较大时，指数中为很大的负数，`exp(-很大)` 容易下溢出为极小的浮点数（例如 1e-20 甚至直接被计算机截断为 0），导致权重崩溃。减去最小值后，表现最好的最优路径超额误差恒为 0，对应 `score = exp(0) = 1.0`，从根本上保证了计算的数值稳健性。
   3. **温度系数 `temp` 的控制机制**：
      - `temp` 偏大：权重曲线被拉平，粒子之间权重差异较小，保留多元假设（保守稳健）；
      - `temp` 偏小：权重产生强烈的两极分化，优质路径权重剧增、劣质路径被重度惩罚甚至归零（激进聚焦）；
      - 在代码中，`temp` 自适应取 `max(np.std(path_nrmse), 0.015)`，本例中约为 `0.045`。
   4. **手算推导与权重规整演算**：
      - 计算相对最优粒子的超额误差序列：
        ```text
        excess_err = path_nrmse - min(path_nrmse)
                   = [0.02, 0.03, 0.02, 0.06, 0.02] - 0.02
                   = [0.00, 0.01, 0.00, 0.04, 0.00]
        ```
      - 带入指数映射与权重归一化：

      | 路径 | path_nrmse | 超额误差 | 指数得分 exp(-超额误差 / 0.045) | 理论归一化权重 | 基准规整权重 (`w_arr`) | 路径评级 |
      | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
      | **Path 0** | 0.02 | 0.00 | exp(-0.00 / 0.045) = 1.000 | ~0.237 | **0.25** | 最优路径，获满额基准权重 |
      | **Path 1** | 0.03 | 0.01 | exp(-0.01 / 0.045) ≈ 0.801 | ~0.190 | **0.20** | 次优路径，适度下调权重 |
      | **Path 2** | 0.02 | 0.00 | exp(-0.00 / 0.045) = 1.000 | ~0.237 | **0.25** | 最优路径，获满额基准权重 |
      | **Path 3** | 0.06 | 0.04 | exp(-0.04 / 0.045) ≈ 0.411 | ~0.098 | **0.10** | 偏差最大，被显著打折降温惩罚 |
      | **Path 4** | 0.02 | 0.00 | exp(-0.00 / 0.045) = 1.000 | ~0.237 | **0.20** | 优质路径，分配稳健权重 |

      > **说明**：理论连续归一化权重求和严格为 1.000；基准示例为了便于后续所有字段（如加权平均 `mean_path`、`pf_val_error`）的人工手算核对，将其规整为满足 `sum(w_arr) = 1.0` 的标准数值 `[0.25, 0.20, 0.25, 0.10, 0.20]`。
      > - 满足权重和为 1.0；
      > - 表现最好的 Path 0/2/4 拥有最高的投票权（20%~25%）；
      > - 表现最差的 Path 3 被降温压制到仅占 10%。

   ##### (6) 机制全流程一览故事版
   1. 模型一次性采样画出 5 条未来走势草稿（粒子）；
   2. 系统利用刚过去 2 天的真实收盘价 `[99.00, 100.00]` 当作标准考卷，核算每条草稿在已知行情上的相对走形程度（`path_nrmse`）；
   3. 走形最小的草稿通过负指数 Softmax 映射赢得高投票权，走形严重的草稿被降温惩罚并压缩投票权；
   4. 最终未来 5 天的各项正式预测指标（期望收盘价、置信区间等），全部以该 `w_arr` 投票权进行加权融合输出。

   ##### (7) 核心概念对照速查表

### 1. 日期 (`date`)
- **字段含义**：本次滚动前瞻推演的锚点日期（决策基准日）。
- **计算逻辑**：取自测试区间各个时间步的交易日时间戳，取值 `2026-04-24`。
- **下游用处**：作为主键与历史行情数据按日合并。策略层在撮合交易时执行严格的 `shift(1)` 对齐，确保在第 `t` 日决策时只能使用 `t-1` 日收盘后产出的预测，杜绝未来函数。

### 2. 预测期望收盘价 (`pred_expected`)
- **字段含义**：持仓至动态最优时界 `optimal_horizon` 当天的跨路径**无偏加权期望收盘价**。
- **设计原理（消除选择性偏置 Selection Bias）**：
  严禁将单路径上的最高冲高价直接当作开仓预期，否则会虚构胜率与赔率幻觉；入场判断必须严格绑定跨路径的无偏加权期望值。
- **计算公式**：
  先计算各个未来时点的加权期望价格序列 `mean_path`：
  ```text
  mean_path[t] = sum(close_arr[i, t] * w_arr[i])  (对所有路径 i 求和)
  target_idx = clamp(optimal_horizon - 1, 0, pred_len - 1)
  pred_expected = mean_path[target_idx]
  ```
- **统一示例演算**：
  跨路径加权期望价格路径 `mean_path`：
  - Day 1 (t=0): `101*0.25 + 100.5*0.20 + 102*0.25 + 99*0.10 + 101.5*0.20 = 101.05`
  - Day 2 (t=1): `103*0.25 + 102.0*0.20 + 105*0.25 + 98*0.10 + 104.0*0.20 = 103.00`
  - Day 3 (t=2): `106*0.25 + 103.0*0.20 + 104*0.25 + 101*0.10 + 105.0*0.20 = 104.20`
  - Day 4 (t=3): `104*0.25 + 105.0*0.20 + 103*0.25 + 102*0.10 + 103.0*0.20 = 103.55`
  - Day 5 (t=4): `102*0.25 + 107.0*0.20 + 101*0.25 + 100*0.10 + 102.0*0.20 = 102.55`
  
  由字段 11 算出最优时界 `optimal_horizon = 3`，对应 Day 3 (`target_idx = 3 - 1 = 2`)：
  ```text
  pred_expected = mean_path[2] = 104.20
  ```
- **下游用处**：
  - **入场 Alpha 核心来源**：在 [kronos_strategy.py: L301](file:///Users/jyy/Documents/github_projects/Kronos/backtest/strategies/kronos_strategy.py#L301) 中计算基础预期收益率：
    ```text
    expected_return = (pred_expected - prev_real_close) / prev_real_close
                    = (104.20 - 100.00) / 100.00 = +4.20%
    ```
  - **信噪比（Z-Score）打分**：作为策略信号强度的核心分子，确保入场决策立足于统计无偏期望，而非虚高的波峰。

### 3. 预测波峰收盘价 (`pred_path_max`)
- **字段含义**：推演区间内个股潜在冲高能力的代表值（加权中位波峰价格）。
- **设计原理（错峰爆发保留）**：
  **逐路径提取最大值，然后取加权中位数（50% 分位数）**。不能先求跨路径平均线再取最大值（在示例中 `max(mean_path)` 只有 104.20），否则各路径错峰冲高（Day 2 冲 105、Day 3 冲 106、Day 5 冲 107）的爆发弹性会被均值抹平。
- **计算公式**：
  ```text
  per_path_peaks[i] = max(close_arr[i, :])  (每条路径各自的最高价)
  pred_path_max = weighted_quantile(per_path_peaks, weights=w_arr, q=0.50)
  ```
- **统一示例演算**：
  提取各路径最高价：`per_path_peaks = [106.00, 107.00, 105.00, 102.00, 105.00]`。
  升序排序与累计权重表：
  | 排序后最高价 | 来源路径 | 路径权重 | 累计权重 |
  | :--- | :--- | :--- | :--- |
  | 102.00 | Path 3 | 0.10 | 0.10 |
  | 105.00 | Path 2 | 0.25 | 0.35 |
  | **105.00** | Path 4 | 0.20 | **0.55** |
  | 106.00 | Path 0 | 0.25 | 0.80 |
  | 107.00 | Path 1 | 0.20 | 1.00 |

  在 50% 分位数（q=0.50）处，累计权重由 0.35 跨越至 0.55，对应价格为 `105.00`：
  ```text
  pred_path_max = 105.00
  ```
- **下游用处**：
  - **多头动态止盈目标位**：在策略层计算潜在波峰回报 `target_return = (pred_path_max - prev_real_close) / prev_real_close = (105.00 - 100.00) / 100.00 = +5.00%`，并映射为持仓跟踪的止盈警戒线。
  - **风控禁令**：绝对禁止用于计算入场预期收益。

### 4. 预测时界终值 (`pred_terminal`)
- **字段含义**：推演窗口末端最后一日（Day 5, `t = pred_len - 1`）的跨路径加权期望价格。
- **计算公式**：
  ```text
  pred_terminal = mean_path[-1]
  ```
- **统一示例演算**：
  ```text
  pred_terminal = mean_path[4] = 102.55
  ```
- **下游用处**：对比 `pred_expected` (104.20) 与 `pred_terminal` (102.55)，可清晰识别推演走势呈现出先冲高后见顶回落的形态，用于判断推演周期末期的趋势收敛情况。

### 5. 预测收盘价_1日 (`pred_close_1d`)
- **字段含义**：推演紧邻次日（未来第 1 个交易日，Day 1）的跨路径加权期望收盘价。
- **计算公式**：
  ```text
  pred_close_1d = mean_path[0]
  ```
- **统一示例演算**：
  ```text
  pred_close_1d = mean_path[0] = 101.05
  ```
- **下游用处**：
  - **动态去偏校准（De-biasing）**：在策略层与次日真实收益对比，计算模型单日的系统性预测偏差：
    ```text
    err_1d = ((pred_close_1d - prev_real_close) / prev_real_close) - realized_1d
    ```
  - **前置体检评估**：在 [skill_evaluator.py](file:///Users/jyy/Documents/github_projects/Kronos/backtest/engine/skill_evaluator.py#L38) 中作为单日预测基准，测算 Rank IC 与次日方向命中率（Hit Rate）。

### 6 & 7. 预测上界与下界 (`pred_upper` / `pred_lower`)
- **字段含义**：波峰发生时点，所有采样路径价格分布的 90% 与 10% 加权分位数，构成 80% 置信区间。
- **计算公式**：
  ```text
  peak_idx = argmax(mean_path)  (或由 auto 确定的最佳时界索引)
  pred_upper = weighted_quantile(close_arr[:, peak_idx], weights=w_arr, q=0.90)
  pred_lower = weighted_quantile(close_arr[:, peak_idx], weights=w_arr, q=0.10)
  ```
- **统一示例演算**：
  在 `peak_idx = 2`（Day 3）处，各路径价格为 `[106.00, 103.00, 104.00, 101.00, 105.00]`。
  排序与累计权重表：
  | 价格 | 来源路径 | 权重 | 累计权重 |
  | :--- | :--- | :--- | :--- |
  | 101.00 | Path 3 | 0.10 | 0.10 |
  | 103.00 | Path 1 | 0.20 | 0.30 |
  | 104.00 | Path 2 | 0.25 | 0.55 |
  | 105.00 | Path 4 | 0.20 | 0.75 |
  | 106.00 | Path 0 | 0.25 | 1.00 |

  - **10% 分位数 (`pred_lower`)**：累计权重 0.10 处对应价格为 `101.00`。
  - **90% 分位数 (`pred_upper`)**：0.90 介于 0.75 与 1.00 之间，线性插值计算：
    ```text
    pred_upper = 105.00 + (0.90 - 0.75) / (1.00 - 0.75) * (106.00 - 105.00)
               = 105.00 + 0.15 / 0.25 * 1.00 = 105.60
    ```
- **下游用处**：量化模型预测的不确定性带宽（Uncertainty Band）；在 Streamlit 看板中绘制预测置信区间带。

### 8. 预测斜率 (`pred_slope`)
- **字段含义**：对期望路径 `mean_path` 进行一阶线性回归拟合出的斜率，并经前收盘价归一化。
- **计算公式**：
  ```text
  slope_val = polyfit(x=[0, 1, ..., pred_len-1], y=mean_path, deg=1)[0]
  pred_slope = slope_val / prev_real_close
  ```
- **统一示例演算**：
  对 `x = [0, 1, 2, 3, 4]` 与 `y = [101.05, 103.00, 104.20, 103.55, 102.55]` 拟合一次方程 `y = a * x + b`：
  解得斜率 `slope_val = 0.355`（即预期平均每日上浮 0.355 元）：
  ```text
  pred_slope = 0.355 / 100.00 = +0.00355 (+0.355%/天)
  ```
- **下游用处**：
  - **入场硬否决**：若 `pred_slope <= 0`，即使点位预测微涨，也判定为整体趋势向下，直接否决：`[风控否决] 预测斜率向下`；此处 `0.00355 > 0` 准予入场。
  - **反转感知去偏（Reversal-Aware）**：均线处于弱势但 `pred_slope > 0` 且预期收益为正时，确认为底部反转，豁免扣除历史负偏差，保护真实买点。
  - **主动离场预警**：当持仓期内 `pred_slope < -0.001` 时，触发看空预警（`bearish_signal`）。

### 9. 预测最大下探 (`pred_min_down`)
- **字段含义**：在持有期（`[0, optimal_horizon]`）内，各路径可能出现的最低价下探跌幅（保守 10% 分位数）。
- **设计原理**：不仅看上涨期望，必须量化开仓后最深潜在浮亏，用于动态调配仓位，防御黑天鹅下探。
- **计算公式**：
  ```text
  per_path_min[i] = min(low_arr[i, :optimal_horizon])
  min_low_val = weighted_quantile(per_path_min, weights=w_arr, q=min_down_quantile)
  pred_min_down = (min_low_val - prev_real_close) / prev_real_close
  ```
- **统一示例演算**：
  持仓期为前 3 天（Day 1 到 Day 3），从 `low_arr` 截取前 3 列提取各路径最低价：
  - Path 0: `min(99.50, 101.00, 104.00) = 99.50`
  - Path 1: `min(99.00, 100.00, 101.50) = 99.00`
  - Path 2: `min(100.00, 103.00, 102.00) = 100.00`
  - Path 3: `min(97.50, 96.00, 97.50) = 96.00`
  - Path 4: `min(100.00, 102.50, 103.00) = 100.00`
  
  最低价升序排序与累计权重表：
  | 最低价 | 来源路径 | 权重 | 累计权重 |
  | :--- | :--- | :--- | :--- |
  | **96.00** | Path 3 | 0.10 | **0.10** |
  | 99.00 | Path 1 | 0.20 | 0.30 |
  | 99.50 | Path 0 | 0.25 | 0.55 |
  | 100.00 | Path 2 | 0.25 | 0.80 |
  | 100.00 | Path 4 | 0.20 | 1.00 |

  在 10% 保守分位数（q=0.10）处，累计权重达到 0.10，`min_low_val = 96.00`：
  ```text
  pred_min_down = (96.00 - 100.00) / 100.00 = -0.0400 (-4.00%)
  ```
- **下游用处**：
  - **动态仓位缩放（Position Sizing）**：在 [kronos_strategy.py: L451](file:///Users/jyy/Documents/github_projects/Kronos/backtest/strategies/kronos_strategy.py#L451) 中，将下探深度与硬止损阈值（如 `hard_stop_loss = 0.04` 即 4%）对比：
    ```text
    depth = abs(pred_min_down) / hard_stop_loss = 0.04 / 0.04 = 1.00
    scale = 1.0 (因为 depth <= 1.0)
    ```
    当下探在止损容忍度内时，不扣减仓位；若预期下探深度 `depth >= 2.0`（例如跌幅达 8% 以上），仓位系数归零，直接放弃开仓。

### 10. 波峰溢价 (`peak_premium`)
- **字段含义**：预测波峰价格相对期望收盘价的超额上冲比例。
- **计算公式**：
  ```text
  peak_premium = (pred_path_max / pred_expected) - 1.0
  ```
- **统一示例演算**：
  ```text
  peak_premium = (105.00 / 104.20) - 1.0 = 0.00768 (即 +0.77%)
  ```
- **下游用处**：用于判断个股脉冲爆发力。若波峰溢价极低，说明走势平钝无弹性，策略可据此进行标的筛选与仓位微调。

### 11. 动态时界 (`optimal_horizon`)
- **字段含义**：模型推演出路径波峰最可能出现的未来交易日天数。
- **计算公式**：
  提取每条路径各自达到最高价的时间索引，取加权中位数后加 1（转化为交易日步长）：
  ```text
  per_path_peak_idx[i] = argmax(close_arr[i, :])
  optimal_horizon = round(weighted_quantile(per_path_peak_idx, weights=w_arr, q=0.50)) + 1
  ```
- **统一示例演算**：
  各路径最高价所在时间索引：
  - Path 0: 索引 2 (Day 3)
  - Path 1: 索引 4 (Day 5)
  - Path 2: 索引 1 (Day 2)
  - Path 3: 索引 3 (Day 4)
  - Path 4: 索引 2 (Day 3)
  
  排序与累计权重表：
  | 时间索引 | 对应路径 | 权重 | 累计权重 |
  | :--- | :--- | :--- | :--- |
  | 1 | Path 2 | 0.25 | 0.25 |
  | **2** | Path 0 | 0.25 | **0.50** |
  | 2 | Path 4 | 0.20 | 0.70 |
  | 3 | Path 3 | 0.10 | 0.80 |
  | 4 | Path 1 | 0.20 | 1.00 |

  中位数（q=0.50）落在索引 2 处：
  ```text
  optimal_horizon = 2 + 1 = 3 (天)
  ```
- **下游用处**：
  - **波动率时间伸缩因子**：`vol_scale = sqrt(optimal_horizon) = sqrt(3) = 1.732`，用于计算信噪比 `signal_score = expected_return_adj / (volatility * vol_scale)`。
  - **持仓生命周期约束**：存入持仓对象 `Position.target_horizon = 3`。
  - **退出状态机触发**：持仓达到 3 天时触发收盘离场评估（波峰止盈或时间止损）。
  - **T+N 市场合规检查**：在 T+1 市场中，若 `optimal_horizon <= 1`，则直接否决开仓（买入当日无法离场）。此处 3 > 1，合规通过。

### 12. 时界 (`horizon_mode`)
- **字段含义**：当前预测批次的时界推演模式标记。
- **取值逻辑**：极值自适应模式为 `'auto'`；固定时界模式则为固定整数（如 `'5'`）。本例为 `'auto'`。
- **下游用处**：元数据回溯，便于下游回测引擎识别是否启用了极值自适应波峰跟踪。

### 13. 采样路径数 (`n_samples`)
- **字段含义**：单日蒙特卡洛随机采样的路径总数（本例为 5 条，实战推荐 20 条）。
- **计算逻辑**：由推演参数 `--samples` 控制。
- **下游用处**：用于检验分位数计算的统计有效性（低于 5 条时降级为最大/极小值），并作为有效粒子数对比的基准分母。

### 14. 粒子滤波置信度 (`pf_confidence`)
- **字段含义**：当前大模型推演走势与该标的近期真实行情的契合程度（0.0 ~ 1.0）。
- **计算公式**：
  ```text
  ESS = 1.0 / sum(w_arr[i] ** 2)
  pf_confidence = clamp(ESS / n_samples, 0.0, 1.0)
  ```
- **统一示例演算**：
  ```text
  sum_w_sq = 0.25^2 + 0.20^2 + 0.25^2 + 0.10^2 + 0.20^2 = 0.215
  ESS = 1.0 / 0.215 = 4.6512
  pf_confidence = clamp(4.6512 / 5, 0.0, 1.0) = 0.9302 (即 93.02%)
  ```
- **下游用处**：
  - **动态安全边际调控**：置信度低于 0.6 时动态提高入场 Z-Score 门槛：
    ```text
    entry_threshold = base_thresh + max(0.0, (0.6 - pf_confidence) * 0.4)
    ```
  - **线性仓位调节**：开仓仓位直接乘以 `pf_confidence` 进行缩水防御。
  - **硬否决线**：若 `pf_confidence < pf_confidence_threshold`（如 0.30），直接一票否决开仓。此处 0.9302 远高于 0.30，准予入场。

### 15. 粒子滤波验证误差 (`pf_val_error`)
- **字段含义**：所有粒子在历史验证窗口上的加权相对跟踪误差 (Normalized RMSE)。
- **计算公式**：
  ```text
  pf_val_error = sum(w_arr[i] * path_nrmse[i])
  ```
- **统一示例演算**：
  ```text
  pf_val_error = 0.25*0.02 + 0.20*0.03 + 0.25*0.02 + 0.10*0.06 + 0.20*0.02
               = 0.005 + 0.006 + 0.005 + 0.006 + 0.004 = 0.0260 (2.60%)
  ```
- **下游用处**：监控模型在最近真实行情下的漂移程度，诊断模型是否失真。

### 16. 有效粒子数 (`pf_effective_n`)
- **字段含义**：统计学意义上的独立有效采样粒子容量（ESS）。
- **计算公式**：
  ```text
  pf_effective_n = 1.0 / sum(w_arr[i] ** 2)
  ```
- **统一示例演算**：
  ```text
  pf_effective_n = 1.0 / 0.215 = 4.6512
  ```
- **下游用处**：诊断粒子退化（Degeneracy）。若权重过度集中在某 1 条路径，ESS 骤降至接近 1，系统自动识别出样本多样性不足。

### 17. 是否插值 (`is_interpolated`)
- **字段含义**：标识该行数据是否为跳步推演时的线性插值填充行。
- **取值逻辑**：真实模型前向推理的锚点日期为 `0`；因 `step_size > 1`（如每 2 天推理一次）由 `np.interp` 线性填充的日期为 `1`。本例为 `0`。
- **下游用处**：
  - **严格数据过滤**：在策略对齐时，默认执行 `df = df[df['is_interpolated'] == 0]` 彻底剔除插值行。
  - **防范学术欺骗**：插值会使时间序列人为平滑，虚假放大 Rank IC 与胜率，因此严禁带插值数据参与技能评估与回测。
